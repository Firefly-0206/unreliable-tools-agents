\paragraph{Parsing, truncation, timeouts.}
\emph{Benchmark.} An answer with finish reason \texttt{length} is \texttt{truncated} and never parsed. Otherwise only a JSON object that ends the answer is accepted (code fences and emphasis stripped); an exact copy of the format template is \texttt{template\_copy}; invalid action or probability give \texttt{bad\_action}/\texttt{bad\_p}; T1 outputs that contain raw tool-call markup in the content are \texttt{tool\_markup\_in\_content}.
H1 is \texttt{incomplete\_model} if any tool accuracy, the stale-report distribution (sum within 0.02 of 1), a fault probability or a persistence flag is missing or out of range; every default applied is recorded and the planner's choice is kept for diagnostics only.
Unparsed answers fall back to ``escalate'' for the headline regret and are also reported on parsed answers only; for ``optimal'' they count as not optimal.
The first record per run key (prompt, model, sample, cap, tag, temperature as sent, hash of extra body) that is a successful response or a model-side timeout is scored. If neither exists, the final record is scored as a failed answer. An HTTP failure (\texttt{api\_error}) can therefore be superseded by a later successful response or model-side timeout. MCWA is computed over parsed answers.
